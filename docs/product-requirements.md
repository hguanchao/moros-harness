## 完整详细产品需求文档（PRD V1\.1）

> 产品名称：Moros Harness（全球唯一自创词，无任何开源/产品重名）
>
> 产品定位：**轻量、本地优先、双端（TUI\+桌面）的办公与编程双场景 Agent 受控执行基座**
>
> 对标产品：Pi Agent（轻量极简），但增加工程Harness能力、双端界面、可控任务执行；同一套管控内核同时覆盖编程工程与日常办公（文档整理、数据分析、报告生成）
>
> 核心特质：轻量不臃肿、不捆绑任何运行时、**无模式概念**（场景由模型自适应 \+ 权限显式控制，ADR\-14）
>
> 变更记录：V1\.1（2026\-11\-14）移除用户可见双模式（ADR\-14）：会话恒为全管控工作模式，「标准模式」降为内部只读策略档（审查会话专用）；只读规划由计划模式承担；事件与历史会话完全兼容。V1\.1（2026\-11\-15）系统提示词最小化与集中化（ADR\-15）：项目类型与本机工具探测不再注入提示词，模型按需探索；功能 4 / 17 移除、功能 12 收窄为 doctor 探测

# 0\. 整体产品总览

## 0\.1 产品解决的核心问题

1. 市面轻量Agent（Pi Agent）**无工程沙箱、无变更管控、无任务隔离**，改代码失控、风险高、不可回溯。

2. 重型Agent框架（LangGraph/AutoGen）**太重、配置复杂、不轻量化、不适合个人全栈开发者**。

3. IDE AI工具**绑定编辑器、无法在服务器/终端独立运行**。

4. 现有Agent要么只能聊天、要么只能干活，**讨论与动手之间缺少受控过渡**（只读规划 → 批准 → 实现）。

5. 绝大多数Agent工具**只有单端界面**，无法同时满足：SSH服务器TUI开发 \+ 本地桌面可视化调试。

6. 大部分Agent工具内置工具集导致**打包体积爆炸**，Moros Harness 采用「仅调度、不捆绑运行时」方案，极致轻量。

## 0\.2 产品核心特性总则

1. **无模式概念**：会话恒为全管控工作模式；只读规划走计划叠加层（/plan），放权程度由审批三档（ask/auto/yolo）显式控制；办公与编程场景由模型自适应（ADR\-14）

2. **双端统一内核**：TUI终端客户端 \+ Electron桌面客户端（同一Core、同一会话、同步数据）

3. **轻量工具调度层**：不打包任何Docker/Node/Python/Git运行时，仅做检测、授权、调度、拦截、审计

4. **完整Harness能力**：沙箱隔离、变更快照、审批机制、任务断点、会话回放、操作审计

5. **模型与业务解耦**：内置 Anthropic Messages、Chat Completions 和 Responses 三个LLM协议端点，支持兼容这些协议的本地或远程模型服务

# 1\. 内核基础模块（共6个功能）

## 功能1：本地优先轻量内核

**作用**

保证 Moros Harness 全程无服务、无后台驻留垃圾进程、无依赖捆绑，启动速度对标 Pi Agent。

**具体行为**

- 单进程启动、瞬时响应

- 不联网也可运行本地模型

- 无集群、无复杂配置、无数据库依赖

## 功能2：内置三个LLM协议端点

**作用**

通过内置的三个LLM协议端点接入兼容的模型服务，不绑定具体模型或服务商。

**内置协议端点**

- Anthropic Messages

- Chat Completions

- Responses

**多供应商配置**

providers.json 注册多个供应商与模型（api 类型 / baseUrl / apiKey / headers / timeout / cost 等），config.toml 顶层 provider \+ model 选择激活项，运行时可切换。apiKey 支持 `${ENV}`、`!command` 或明文——三者同等合法，选择权在使用者，不做告警；远程供应商缺少凭据时标记不可用，本地 loopback 服务可留空。密钥在配置回显、诊断与审计中统一显示为 `***`；TUI 运行期间产生的非致命配置诊断显示在对话流顶部警告区与状态行（完整文本不因状态行截断而丢失）；备用屏期间隔离所有 stderr 输出，退出界面后统一回放到主屏，不得破坏全屏渲染。

**辅助模型（压缩 / 审查）**

config.toml 用两个顶层键把辅助任务指向另一个模型（snake_case 与 camelCase 等价）：

- `compact_model` / `compactModel`：上下文摘要用的模型。
- `review_model` / `reviewModel`：auto 档高危动作的审查模型。

取值支持两种写法：`modelId`（省略供应商，取 config.toml 的 `provider`）与 `provider/modelId`（如 `hiyo/deepseek-v4.1-flash-1017`）；斜杠前的片段必须是 providers.json 里已注册的供应商才按供应商解析，否则整串视为模型 id（`meta-llama/llama-3-70b` 这类带斜杠的 id 不会被拆坏）。两个键都不填时复用 config.toml 的 `model`——auto 档默认带审查，只是审查者与被审查者是同一个模型；要第三方视角就显式配另一个模型（配成同一个时启动告警留痕）。模型引用解析失败只告警并降级（压缩回退会话模型、审查退回人工），不让会话跑不起来；审查超时（固定 30 秒）、报错、答复不可解析一律 fail-closed 退回人工。

会话运行支持附带预处理后的 PNG/JPEG/WEBP/GIF 图片；模型未声明 image 输入时拒绝该请求。图片数据保存在会话附件目录，事件只保存附件元数据。图片来源支持本地文件、剪贴板与 http/https 链接：链接仅在用户显式粘贴或拖入时抓取，只允许 http/https，解析后命中私网/回环/链路本地/保留地址即拒绝，重定向逐跳复检（最多 3 跳），下载按流式累计截断（单张 8 MB、10 秒超时），落盘前仍需通过文件头与边长校验；来源 URL 记入附件元数据供审计。

## 功能3：会话隔离机制

**作用**

每个对话/任务会话完全隔离，上下文不串扰、不污染。

## 功能4：项目上下文自动加载（已移除）

> 2026-11-15 移除（ADR-15）：项目类型与上下文改由模型按需探索（read/glob/bash 自行读取项目文件），不再预扫描注入系统提示词。

## 功能5：全局权限沙箱内核

**作用**

所有文件操作、Shell、Docker操作**必经内核拦截校验**，是整个产品安全基座。

## 功能6：双端内核统一复用

**作用**

TUI端、桌面端**共用同一个Core逻辑**，行为完全一致、会话互通、配置互通。

# 2\. 场景自适应与管控策略（共5个功能槽位，其中功能11已移除）【核心差异化】

> 2026\-11\-14（ADR\-14）收敛：原「双模式交互系统」（标准/创造）的用户可见概念移除，会话恒以全管控工作模式运行；`standard` 策略档降为内部只读档（审查会话专用）。一期已验收的双模式实现保留事件兼容（mode 枚举不变，历史会话照常回放）。办公与编程不设切换开关，由模型自适应。

## 功能7：场景自适应（原标准模式）

**作用**

同一套内核同时服务办公与编程场景，无需用户选择或切换：模型从请求内容与工作区上下文自行适配——整理文档、分析表格、生成报告与改代码、重构、排错走同一条执行路径。

**边界**

- 不设「办公模式 / 编程模式」等场景切换入口

- 权限不随场景变化：只读由计划叠加层控制，放权由审批三档控制

## 功能8：全管控工作模式（原创造模式，唯一会话形态）

**作用**

会话即工作流，开启**全套沙箱、快照、审批、审计、断点、回放**能力——改代码、重构、部署、排错，与批量整理文件、数据处理等办公任务共用同一套管控。

**内部说明**

- `standard` 策略档（只读：写与命令直接拒绝并说明原因）仅供内部只读会话使用，当前唯一消费者：只读审查（/review）

- 子代理一次性会话与主会话同一策略档，写动作经审批（ADR\-14 修正）

## 功能9：会话内只读规划（原单会话无缝模式切换）

**作用**

「讨论 → 动手」的受控过渡由计划模式承担：`/plan` 打开只读叠加层（写与命令直接拒绝），模型探索并提交计划成卡，批准后进入实现；上下文全程保留。无模式切换动作。

## 功能10：策略状态可视化（原模式状态标识）

**作用**

界面实时显示审批档徽标（Ask / Auto / Yolo）与计划模式标记，TUI 页脚与桌面端一致；不再显示模式徽标。

## 功能11：模式记忆持久化（已移除）

> 2026\-11\-14 移除（ADR\-14）：无模式概念后无记忆对象；新会话的默认放权程度由 config.toml 的 `approval` 配置承担。

# 3\. 轻量全栈工具调度系统（共6个功能）【解决体积大痛点】

## 重要前置说明

所有工具 **仅调度、不打包、不嵌入运行时**

Moros Harness 只携带：调用协议、参数校验、权限校验（沙箱/审批）、拦截规则（denylist）、检测逻辑

本机有什么工具，就用什么工具；没有则禁用、提示，**不会增加包体积**

## 功能12：系统环境自动检测

**作用**

自动检测本机是否存在：Git / Docker / Node / Python / Go 等开发工具（只探测、不下载不安装），供 `doctor` 检查报告使用。

**边界（ADR\-15）**

- 探测结果**不再注入系统提示词**；模型按需用工具自行探测本机能力（如 `python --version`）

## 功能13：文件操作工具调度

**包含能力**

读取文件、编辑与新建文件、目录遍历（glob）、代码搜索（grep）；删除、批量修改等经 shell 命令执行

## 功能14：Shell命令受控调度

**作用**

允许Agent执行命令，但**内置拦截规则（denylist）硬拦截高危命令**（rm \-rf /、格式化、系统篡改）

## 功能15：Git工作流调度

**作用**

通过 shell 工具执行 Git 工作流操作（status、add、commit、diff、log、branch），环境探测适配命令策略

## 功能16：Docker环境调度

**作用**

通过 shell 工具操作本机 Docker（构建、启动、重启、查看日志、查看容器），环境探测适配

## 功能17：前端/后端工程识别调度（已移除）

> 2026-11-15 移除（ADR-15）：工程类型识别职责移交模型按需探索；工程命令约定由模型从项目文件（package.json 等）自行读取，不再由 harness 预判注入。

## 功能18：自定义用户工具扩展（已移除）

> 2026-11 移除：保持内核精简；生态级扩展规划走 MCP client（V1.1，见开发设计文档）。

# 4\. Harness核心管控系统（最强差异化，共10个功能）

## 功能19：文件沙箱路径隔离

**作用**

强制Agent**只能操作当前项目目录**，禁止跨目录篡改系统文件、上级目录文件。

## 功能20：操作前置审批机制

**作用**

工作会话中：所有**文件删除、批量修改、高危命令**经审批闸门，ask 档必须用户点击确认才可执行。审批策略三档可配：ask（每次询问，默认）/ auto（按命令风险判定：low/medium 静默放行并留审批事件，high 先交审查模型判定（缺省复用主模型，可用 `review_model` 指定），通过则放行并记 `approval.reviewed` 事件，拒绝或审查不可用则转人工审批）/ yolo（全放行、不问）。denylist 三档一律硬拦截，不随档位降级（对齐 Claude Code 的 bypass 断路器与 Gemini CLI 的 deny 规则）；路径沙箱在所有档位保留。TUI 内可经 `Shift+Tab` 在会话内切换三档（Ask/Auto/Yolo，页脚徽标与输入框边框随档位变化；不回写配置，重开恢复配置默认）。审批卡另提供「本会话放行」（`a`）：shell 按命令前缀、其余按工具名记住，同一动作不再重问；卡片右上角标出 risk（high/medium），供使用者判断该不该点同意。

## 功能21：代码变更快照系统

**作用**

Agent通过文件工具修改文件时，自动保存diff快照，可随时查看改动细节。

## 功能22：一键变更回滚

**作用**

对Agent通过文件工具的改动，支持单步回滚、整任务回滚；shell 命令改动由审批闸门与全链路审计兜底。

## 功能23：任务断点暂停/继续

**作用**

长任务（多文件重构、迁移、脚手架生成）可随时暂停、继续、不丢失进度。

## 功能24：完整会话回放

**作用**

可从头到尾回放Agent所有推理、工具调用、文件变更、命令执行。

## 功能25：全链路审计日志

**作用**

记录：时间、动作、文件路径、命令内容、模型输出、用户操作

**落点**：以会话 `events.jsonl` 为唯一事实源；Core `readAudit()` 按项目动态聚合查询（接口保留供桌面端评估复用），项目目录不另写审计投影文件；CLI/TUI 二期不提供查询入口。

## 功能26：任务步数上限与防护

**作用**

防止Agent死循环调用工具：主循环步数上限（maxTurns）、连续失败熔断（内置）、流式静默保护、工具结果超限落盘（spill）。

## 功能27：上下文自动压缩

**作用**

长会话上下文接近模型窗口时自动压缩：旧消息摘要化、保留最近原文，防止上下文超限；压缩过程记录事件、可回放。摘要默认复用激活模型，可用 `compact_model` 指定更便宜或上下文更大的模型。

## 功能28：项目变更总结报告

**作用**

任务结束自动生成：本次改动了哪些文件、解决了什么问题、变更清单。

## 功能40：工作区指令（ADR-16）

**作用**

每轮自动读取两级 AGENTS.md 指令并注入系统提示词：用户级 `~/.moros/AGENTS.md`（全局偏好，直接生效）+ 项目级 `<项目根>/AGENTS.md`（仓库协作约定，**须先过工作区信任**，未信任不注入）。项目级冲突时优先于用户级（更具体），但都不覆盖 harness 管控策略与使用者对话中的直接指示。

**边界**

- 单文件 32KB 截断；损坏跳过并告警；不做嵌套子树作用域与 .local 叠加层（V1.1）

## 功能39：子代理任务委派

**作用**

模型可通过 `task` 工具把独立子任务委派给一次性子代理：Core 在同一进程内新建一次性会话（与主会话同一策略档、受限工具面、无 task 工具防递归），跑完后只把最终结果回传主对话，子会话随即删除。主对话流按子代理组卡片实时显示每个委派的运行状态、步数与耗时；审批沿用主会话档位，子代理内的写类动作同样过统一拦截管线。委派受严格限制：一次一个子代理串行执行、递归深度为 1、子代理无法再委派；子会话事件流独立落盘（审计完整保留），主会话只记 task 调用与结果。中止主回合时同步中止子代理。

# 8\. 产品核心约束（必须严格遵守开发）

## 约束1：永远不捆绑运行时

所有 Docker / Git / Node / Python 全部**调用本地已有环境**，绝不打包进二进制。

Moros Harness 自身以 npm 包交付，依赖本机 Node.js ≥ 22；桌面端（Electron）自带运行时，为独立分发形态。

## 约束2：体积必须极轻量

对标 Pi Agent 体积，保持小型二进制，不臃肿。

## 约束3：双端内核100%统一

TUI和桌面**逻辑、权限、规则、模型、会话完全一致**，不存在双端行为分裂。

## 约束4：无模式概念（ADR\-14）

- 会话恒为全管控工作模式：严谨、可控、可审计、可回滚

- 只读需求由计划叠加层（/plan）承担；放权程度由审批三档（ask/auto/yolo）显式控制

- 办公与编程场景由模型自适应，不设场景切换开关

## 约束5：模型完全解耦

业务逻辑不绑定任何大模型API。

# 9\. 开发分期（三期，严格串行）

1. **一期：Core 内核**（无 UI）——内核基础、LLM 三端点、工具调度、Harness 管控、双模式与恢复，以自动化测试验收。

2. **二期：TUI 与 CLI 入口**——终端界面全部功能（功能 29~33）与 `moros` / `mrh` 命令。

3. **三期：桌面端与发布**——Electron 六页面（功能 34~38）、双端一致性验收、跨平台打包。

上一期验收全绿才进入下一期。功能 1~28 的一期 Core 实现状态和自动化验收证据见 `docs/一期验收清单.md`；仅属于 TUI、CLI 或桌面交互的能力按后续阶段验收。

# 10\. 产品最终一句话官方定义（定稿）

Moros Harness 是一款**类 Pi 轻量体验、双端互通、不捆绑运行时**的办公与编程双场景 Agent Harness：会话恒为全管控工作模式，无模式切换——只读规划走计划叠加层，放权程度由审批三档显式控制，办公与编程场景由模型自适应。通过沙箱隔离、变更快照、审批审计、任务回放解决传统 Agent 失控、不可回溯、体积臃肿的问题，并以同一套管控内核覆盖编程工程与日常办公两类场景。
